# 拾迹 Trace — AI 协作学习日志框架 · 功能描述文档

> 工作名「拾迹 / Trace」——拾起每天和 AI 对话留下的痕迹，汇成成长轨迹。
> 文档版本 v1.0 · 2026-07-02

---

## 一、Context（为什么做这个）

你是 AI 时代的开发者/学习者。每天大量使用 AI 编码工具（Claude Code 等）解决问题，但**学到的东西散落在一条条对话里，几天后就忘了**，也说不清"这个月我到底成长了什么"。调研证实这是 AI 协作学习者的两大普遍痛点：

- **冒名顶替感**（"感觉自己没学到东西"）—— [FreeAgent 工程博客](https://engineering.freeagent.com/2023/08/22/how-to-survive-imposter-syndrome-in-your-software-engineering-internship/)、[r/Frontend 讨论](https://www.reddit.com/r/Frontend/comments/uxprn5/)
- **学了就忘**—— [freeCodeCamp 论坛](https://forum.freecodecamp.org/t/dealing-with-forgetting-what-i-learn/248624)，公认解法是**记下来 + 周期复习**

现有工具各做一段，没人把它们串起来（见 [调研附录 A](#附录-a同类工具现状与空白)）：

| 已有能力 | 代表工具 | 缺的那一段 |
|---|---|---|
| 导出 Claude Code 对话 | claude-code-transcripts / claude-code-log | 只转格式，不提炼 |
| 把对话变笔记 | NoteGen / Mem0 | 不按学习主题分类 |
| 从 git 生成日报 | dev-journal | 只记"做了什么"，不记"学到/挣扎了什么" |
| 学习打卡游戏化 | Athenify / Trophy.so | 全靠手动输入 |

**本项目要填的空白**：把 `对话采集 → 技术主题提取 → 每日结构化笔记 → 游戏化成长轨迹` 这四段自动串成一条流水线，且**零额外操作**——你照常用 Claude Code，剩下的它替你记。

**核心口号**：多对话 · 多犯错 · 多学习。设计上要奖励"生产性失败"（详见[游戏化设计](#七游戏化机制设计全部渲染为-markdown)）。

---

## 二、核心理念（4 条原则，所有功能都向它们对齐）

1. **零摩擦**：不要求你每天手动写。数据源是 Claude Code 本地已经在写的 JSONL 文件，框架只读不拦。
2. **从错误中学习**：踩坑的对话比顺利的对话更值钱——参考 Manu Kapur 的[生产性失败理论](https://www.manukapur.com/productive-failure/)。
3. **公开成长**：纯 Markdown + git，天然能当 TIL 仓库发布，自带社交监督（[#100DaysOfCode 同理](https://podcast.scrimba.com/159/transcript)）。
4. **本地优先 + 可拔插**：笔记和原始数据全留本地；LLM 调用层抽象成接口，换模型不改代码。

## 三、系统总览（数据流）

```
  ┌─────────────┐   每日触发(定时/手动)    ┌──────────────┐
  │ Claude Code │ ─────────────────────▶  │  ① 采集器    │  扫描本地 JSONL
  │ ~/.claude/  │                         │  Collector   │  按天分组、去重
  └─────────────┘                         └──────┬───────┘
                                                 │ 当天对话文本
                                                 ▼
  ┌─────────────┐    结构化 JSON      ┌──────────────┐
  │ GLM/DeepSeek│ ◀─────────────────  │  ② 提取器    │  主题/问题/踩坑/概念
  │ (OpenAI兼容)│ ──────────────────▶ │  Extractor   │  response_format 强约束
  └─────────────┘                      └──────┬───────┘
                                              │ 结构化数据
                                              ▼
  ┌─────────────┐   notes/2026-07-02.md ┌──────────────┐
  │  Jinja2 模板 │ ◀──────────────────   │  ③ 生成器    │  渲染每日笔记
  │  Template   │ ──────────────────▶   │  Generator   │  + 当日徽章/计数
  └─────────────┘                       └──────┬───────┘
                                              │
                                              ▼
  ┌─────────────┐   README.md / STATS.md ┌──────────────┐
  │  git 仓库    │ ◀──────────────────── │  ④ 聚合器    │  重算连续天数
  │  (可发布)   │                        │  Aggregator  │  技能树/热力图/总计数
  └─────────────┘                        └──────────────┘
```

**触发方式**：Windows 计划任务每日晚跑一次；或手动 `python -m shiji today`。

## 四、技术选型（已根据你的选择定稿）

| 决策项 | 选定 | 理由 |
|---|---|---|
| 语言 | **Python 3.11+** | LLM SDK + JSONL 解析 + 文本处理是 Python 的甜区，几天能出 MVP |
| LLM | **OpenAI 兼容接口**（默认智谱 GLM） | 你现在 Claude Code 走的就是 glm-5.2，key 已有；DeepSeek/Qwen 同协议可热换 |
| LLM SDK | `openai` 官方包，改 `base_url` | 一行换厂商，不改业务代码 |
| 结构化输出 | `response_format: json_object` + pydantic 校验 | 跨 GLM/DeepSeek/Qwen 最稳；json_schema 部分厂商不全支持 |
| 笔记渲染 | **Jinja2 模板** | 模板和代码分离，改笔记样式不动逻辑 |
| 状态存储 | SQLite（`trace.db`） | 记"哪些会话/天已处理过"，避免重复跑 LLM 烧钱 |
| CLI | `typer` | `shiji today` / `shiji collect` 命令式，最简单 |
| 调度 | Windows 任务计划程序 | 你在 Windows；也可 WSL cron |
| 前端 | **无** | 纯 Markdown，VS Code / GitHub 直接看 |

**LLM 接入示例（GLM）**：`base_url=https://open.bigmodel.cn/api/paas/v4/`，用现有 key。配置写在 `.trace/config.toml`。

> 注：包名用 `shiji`（拾迹拼音），避开 Python 标准库 `trace` 模块冲突——否则 `python -m trace` 会撞车。

## 五、功能模块详解

### 模块 ① 采集器 Collector

**输入**：`~/.claude/projects/<编码后的cwd>/<sessionId>.jsonl`（已在本机验证存在，3 个项目目录）。
**核心逻辑**：
- 递归扫描所有 `.jsonl`，逐行 `json.loads`，按 `type` 过滤——只留 `user` / `assistant`。
- 提取字段：`timestamp`（按本地时区转日期）、`message.role`、文本内容、`tool_use` 工具调用、`cwd`、`gitBranch`。
- 跳过噪声类型：`mode` / `attachment` / `file-history-snapshot` / `system`。
- 用 `parentUuid→uuid` 还原对话顺序。
- **代表性抽取**：真实一天可能有几十万字，按轮截断 + 均匀采样 + 字符上限（默认 24000）压到便宜且聚焦。
- **按天分组**：以 `timestamp` 的本地日期为 key。

**输出**：喂给 LLM 的当天文本（已截断）。

**边界**：默认只采集 Claude Code；ChatGPT/Cursor 留到 Phase 3。

### 模块 ② 提取器 Extractor

**输入**：一天的对话文本。**输出**（pydantic 强校验）：

```json
{
  "date": "2026-07-02",
  "technologies": [
    {"name": "Docker", "what_learned": "理解了镜像分层", "confidence": 0.8}
  ],
  "questions_asked": ["怎么把容器代码挂载到宿主机?"],
  "mistakes_and_debugging": [
    {"problem": "permission denied", "root_cause": "volume 权限", "resolved": true}
  ],
  "concepts_learned": ["容器 vs 镜像的区别"],
  "summary": "一句话总结今天",
  "struggle_level": "medium"
}
```

**Prompt 要点**（写在 `prompts/extract.md`）：
- 只抽**真实出现过的**技术关键词，禁止臆造。
- `mistakes_and_debugging` 是**最重视的字段**——错误 + 根因 + 是否解决，直接喂给游戏化的"踩坑奖励"。
- `confidence` 让后续可过滤低把握的噪声。

**成本控制**：采集器已截断；`trace.db` 按天缓存结果，重跑不重复调 LLM。

### 模块 ③ 生成器 Generator

把提取器输出 + 当日游戏化数据，用 Jinja2 渲染成 `notes/YYYY-MM-DD.md`。模板见[第六节](#六每日笔记模板这是你最常看到的成品)。

**幂等**：同一天重跑会覆盖当天文件，但 `<!-- user-notes -->` 锚点区你手写的补充会被保留不覆盖。

### 模块 ④ 聚合器 Aggregator

每次生成笔记后重算并覆写：

- **`README.md`** — 成长轨迹总览：连续天数、累计学习天数、已攻克问题数、已点亮技能数、活跃热力图、技能进度表、徽章墙、最近笔记。
- **`STATS.md`**（Phase 1）— 每个技术的出现次数与时间分布、每周反思汇总。

## 七、游戏化机制设计（全部渲染为 Markdown）

> 原则：游戏化服务 SDT 三要素（自主/胜任/联结），不当贴纸工厂。依据 [Khaldi 2023 系统综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC9887250/)。

| 机制 | 怎么实现 | 为什么有效 / 怎么防反噬 |
|---|---|---|
| **连续天数 🔥** | README 顶部展示，按日笔记生成计连续 | Duolingo 数据 7 天连续后留存 ×2.4；**但设宽限日**（默认 3 天不让归零），避免焦虑刷量（[streak creep](https://thedecisionlab.com/insights/consumer-insights/streak-creep-the-perils-of-too-much-gamification)） |
| **技能进度条 🌳** | 每个技术按出现次数算节点进度，渲染成 `███░░░░░ 3/8` | 让进步可视化、空间化；进度条而非等级，降低"刷"的冲动 |
| **徽章 🏅** | 触发条件算出，当天笔记 + README 徽章墙展示 | 只奖励**真实学习行为**（解锁新技术/解决错误/深挖概念），不奖励对话条数 |
| **已攻克问题计数** | README 大字 `🐛 已攻克问题：47` | **本项目招牌**：把整个学习历程重构成"攻克的困难累计"，正面化犯错，呼应口号 |
| **生产性失败高亮** | 踩坑段在笔记里置顶 + 标星 | Kapur 理论：先挣扎后弄懂学得更深 |
| **周/月复盘** | 每周自动生成 `notes/week-W.md` 汇总 | 周期复习对抗"学了就忘" |

**已实现的徽章**：🧭 探索者（5+ 技术）· 🧭🧭 老练探索者（15+）· 🔥 7 天连击 · 🔥🔥 30 天连击 · 🐛 Debug 侦探 Lv.1/2/3（攻克 5/10/20+ 问题）· 📖 深挖者（某技术跨 3+ 天）。

## 九、配置与隐私

- **`.trace/config.toml`** 关键项：`llm.base_url` / `llm.api_key_env`（读环境变量不硬编码）/ `llm.model` / `streak.grace_days` / `sources.exclude_cwds`。
- **隐私**：笔记和原始数据全在本地；**但提取器会把当天对话文本发给 GLM**。CLI 启动会提示；后续可加：
  - `exclude_cwds`：跳过指定 cwd 的对话（如公司敏感项目）；
  - `redact` 选项：发送前正则脱敏；
  - `local_model=true`：切换到本地 Ollama，零外发。

## 十一、验证方式（怎么确认它真的 work）

1. **采集 dry-run**（不调 LLM）：`uv run shiji collect --dry-run` → 打印今天解析到的会话数、轮数、涉及 cwd。
2. **端到端**：`uv run shiji today` → 打开 `notes/今日.md`，检查技术关键词是否真实出现过、踩坑段是否抓对、徽章触发是否合理。
3. **幂等**：同一天连跑两次，第二次应命中缓存不重复调 LLM、不覆盖 `<!-- user-notes -->` 区。
4. **手动抽检**：对照原始 JSONL 看提取有没有漏掉重要主题或臆造不存在的技术。

## 附录 B：关键设计决策记录

- **纯 Markdown 而非网页**：你选的。附带收益——天然版本控制 + 可发布 = 免费实现"成长轨迹"和"learn in public"，省掉整个前端。
- **游戏化渲染进 Markdown**：技能条用 `████░░`、徽章用 emoji、热力图用字符块，零依赖。
- **默认 GLM**：你 Claude Code 已在用 glm-5.2，key 现成；LLM 层抽象成接口，DeepSeek/Qwen/Ollama 可热换。
- **奖励犯错而非奖励条数**：XP/徽章只挂"真实学习行为"，避免刷对话——这是本项目区别于普通打卡工具的灵魂。
